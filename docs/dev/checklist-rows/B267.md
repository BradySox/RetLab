### B267 — The map draws without the video card · §8 · ☐ UNTESTED

**What changed (2026-10-21):** the campaign map renders in software (Chromium
`--disable-gpu --disable-gpu-compositing`, Qt Quick's software scene graph), so the
Retribution process stops holding GPU memory next to DCS. Before: `python.exe` held
3,981 MB of dedicated VRAM mid-mission, with the map hidden by the earlier pause (#1354,
now removed).

**Pass:** restart the app. In Task Manager, Details tab, add the "Dedicated GPU memory"
column (or `typeperf "\GPU Process Memory(*)\Dedicated Usage"`). With the map open, and
again during a mission, `python.exe` stays under ~300 MB, and `QtWebEngineProcess.exe`
stays under ~100 MB. The map still pans and zooms acceptably (no multi-second stalls),
and the map shows the new turn after debrief.

**Fail signature:** `python.exe` still holds GBs of dedicated GPU memory with the map
open (a flag was not picked up: check `QTWEBENGINE_CHROMIUM_FLAGS` and `QT_QUICK_BACKEND`
are not overridden in the environment); the map is blank or black; panning or zooming
stutters badly on a large campaign.
