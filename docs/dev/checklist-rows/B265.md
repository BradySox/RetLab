### B265 — No app crash after mission end; a native crash leaves faulthandler.log · §8 · ☐ UNTESTED

**What changed (2026-10-21):** the debrief poll, the sim clock's updates and the map's
saved-point notices reach Qt on the GUI thread, and the waiting window lets go of the
debrief signal when it closes. The app writes `logs/faulthandler.log`, one header line per
start.

**Pass:** fly two missions in one session (Take off, end the mission, Accept results, then
Take off again), with the F10 map open and a saved point added on it during one. The app
stays up through both debriefs and for a few minutes after each "Mission end detected" line
in `logs/retribution.log`. `logs/faulthandler.log` has one `--- DCS Retribution ... started`
line per app start and no stack under the last one.

**Fail signature:** the app vanishes with Windows event 1000 (`pyside6.abi3.dll`,
0xc0000005); `logs/faulthandler.log` then holds a `Windows fatal exception: access
violation` stack per thread under the last header, and the thread marked `Current thread`
is the code to fix next. No header line at all: the log was not opened.
